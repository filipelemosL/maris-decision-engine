PASSO 1️⃣ : MANTER A API RODANDO (Escolha 1 opção)
─────────────────────────────────────────────────

🥇 OPÇÃO A: PM2 (Recomendado) - Auto-restart automático
   
   # Terminal novo:
   $ npm install pm2 -g
   $ pm2 start api_producao.py --name "mde-api" --interpreter "python"
   $ pm2 save
   $ pm2 startup

   ✅ Vai rodar 24/7, reinicia se cair, inicia ao ligar o PC

   Comandos úteis:
   - pm2 list              | Ver status
   - pm2 logs mde-api      | Ver logs
   - pm2 restart mde-api   | Reiniciar

─────────────────────────────────────────────────

🥈 OPÇÃO B: Em um Terminal (Simples)
   
   $ .venv\Scripts\Activate.ps1
   $ python start_api.py

   ✅ Fácil, mas precisa deixar o terminal aberto

─────────────────────────────────────────────────

🥉 OPÇÃO C: Windows Task Scheduler (Automático)
   
   1. Criar arquivo start_api.bat na pasta do projeto
   2. Abrir Task Scheduler do Windows
   3. Criar nova tarefa para executar ao login
   
   ✅ Automático, mas mais complexo de configurar

PASSO 2️⃣ : EXPOR API PARA INTERNET (Escolha 1 opção)
─────────────────────────────────────────────────────

🥇 OPÇÃO A: ngrok (Mais fácil) - URL pública em segundos
   
   1. Download: https://ngrok.com/download
   2. Extrair em uma pasta
   3. Abrir terminal ali e rodar:
      $ ./ngrok http 5000
   
   4. Você verá uma URL tipo:
      Forwarding    https://xxxx-yyyy.ngrok.io -> http://localhost:5000
   
   5. Use essa URL no seu Vercel!

   ✅ Muito fácil
   ⚠️  URL temporária (muda ao reiniciar - versão gratuita)

─────────────────────────────────────────────────

🥈 OPÇÃO B: IP Local (Se na mesma rede WiFi)
   
   1. Descobrir IP:
      $ ipconfig
      
      Procurar por: IPv4 Address: 192.168.X.X
   
   2. Use: http://192.168.X.X:5000 no Vercel
   
   ✅ IP fixo na rede
   ⚠️  Só funciona se frontend e API na mesma rede

─────────────────────────────────────────────────

🥉 OPÇÃO C: Cloud (Melhor para produção)
   
   Deploy em Render.com (gratuito):
   
   1. Criar conta: https://render.com
   2. Novo "Web Service"
   3. Conectar repo GitHub
   4. Render gera URL: https://mde-api-xxxxx.onrender.com
   
   ✅ URL fixa e profissional
   ✅ Roda 24/7 em nuvem
   ⚠️  Leva ~5 minutos para fazer deploy

PASSO 3️⃣ : INTEGRAR COM FRONTEND NO VERCEL
───────────────────────────────────────────

Se você já tem um projeto Next.js/React:

1. Arquivo .env.local (ou .env.production):

   NEXT_PUBLIC_API_URL=https://sua-url-aqui.com
   NEXT_PUBLIC_LOCATION_ID=1

2. Arquivo src/api/weather.js:

   const API_URL = process.env.NEXT_PUBLIC_API_URL;

   export async function getOperationalStatus(locationId = 1) {
     const res = await fetch(`${API_URL}/api/operational-status/${locationId}`);
     return res.json();
   }

   export async function getAllLocationsStatus() {
     const res = await fetch(`${API_URL}/api/all-locations-status`);
     return res.json();
   }

3. Usar em um componente React:

   import { getOperationalStatus } from '@/api/weather';
   
   export default function Dashboard() {
     const [status, setStatus] = useState(null);
     
     useEffect(() => {
       getOperationalStatus(1).then(setStatus);
     }, []);
     
     if (!status) return <div>Carregando...</div>;
     
     return (
       <div>
         <h2>{status.location.name}</h2>
         <p>IEA: {status.decision.iea_score}</p>
         <p>Status: {status.decision.operational_status}</p>
         <p>Pode Operar: {status.decision.is_operational ? '✅' : '❌'}</p>
       </div>
     );
   }

4. Deploy:

   $ git push               # Para seu GitHub
   
   No Vercel Dashboard:
   → Novo projeto
   → Selecionar repo GitHub
   → Add Environment Variables (NEXT_PUBLIC_API_URL)
   → Deploy!
